# Development

## Prerequisites

- Node.js (LTS)
- Xcode (for iOS) / Android Studio (for Android)
- Cocoapods (`gem install cocoapods`)

## Quick start

```bash
npm install
npx expo run:ios       # or: npm run ios
npx expo run:android   # or: npm run android
```

## Rebuilding native projects

The `ios/` and `android/` directories are gitignored. They are generated by Expo prebuild and should not be committed. If you need a clean rebuild (e.g. after changing `app.json` plugins, native permissions, or adding a new native module):

```bash
npx expo prebuild --platform ios --clean
npx expo run:ios
```

This regenerates `ios/` from scratch based on `app.json` and installed Expo plugins.

## Path aliases

| Alias | Maps to |
|-------|---------|
| `@/*` | `./src/*` |
| `@/assets/*` | `./assets/*` |

Configured in `tsconfig.json`. Use these in all imports — never use relative `../../` paths from screens or hooks into other top-level folders.

## Strings

All user-visible copy is in `src/strings/app-strings.ts`. When adding new screens or features, add strings there first, then reference `appStrings.yourSection.yourKey` in components. This keeps the door open for future i18n.

## Design tokens

Visual constants come from two files mirroring Stitch design exports:

- `src/constants/stitch-cupertino-home.ts` — home screen + settings colors, radii
- `src/constants/onboarding-focused.ts` — onboarding screen colors, layout dimensions

Generic tokens (spacing, font families, platform-specific values) live in `src/constants/theme.ts`.

Never hardcode hex colors in components — always reference a token.

## Adding a new module

1. Create `src/modules/your-module/` with an `index.ts` barrel
2. Keep internal files private — only export through `index.ts`
3. Never import from another module's internal files; always use its barrel

## Key Expo config notes

- `app.json` includes `NSPhotoLibraryUsageDescription` under `expo.ios.infoPlist` for photo library access
- `expo-image-picker` plugin configures the permission prompt text
- `experiments.reactCompiler: true` enables the React Compiler
- `experiments.typedRoutes: true` enables type-safe routing
